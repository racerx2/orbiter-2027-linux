## Buried structures (the user's bug: dark footprints on the terrain, no building, KSC, Earth tree)
Root cause (code, confirmed in the client log: Cape Canaveral `nsas=4`):
- The core merges a base's generic objects (BLOCK, HANGAR, TANK ..., about 150 in Canaveral.cfg) into a few base-wide meshes, one per texture. VBase::RenderGroundShadow projects each mesh onto one plane; for a mesh with bounding radius >= 250 m (every merged one) the plane goes through the terrain at the base reference point, i.e. base level.
- ShadowTech pass P1 (Mesh.fx) draws that projection with ZEnable false and only discards what lies under the plane (alpha = height over the plane). Objects standing where the streamed terrain is higher than base level are hidden by the terrain, but their shadows, lying on the base-level plane under the terrain, are drawn over it: the footprints in the shot.
- With SceneShadows 1 the cascades cover the base near the camera and the stencil is skipped (a buried object's map depth is behind the terrain receiver, so it shades nothing); beyond the cascades and with SceneShadows 0 the stencil path showed the bug.
Fix (both settings):
- Mesh.fx ShadowMeshTechExVS: each projected vertex is pulled toward the camera along its view ray by 2 m / sin(view slope to the plane) (slope floored at 0.01, pull at most half the distance): no screen shift, ground up to 2 m over the plane still takes the shadow. Pass P1: `ZEnable = true; ZFunc = LessEqual;` (ZWrite off, stencil unchanged). Terrain more than 2 m over the plane now hides the shadow; drawn right after the terrain and base tiles (VPlanet::Render), so only terrain occludes it, structures and vessels are drawn later as before.
- VBase.h/.cpp: UpdateBuried() at the lighting check (0.1 s): a structure mesh whose top (AABB max y) lies under the loaded terrain (vPlanet::GetElevation, filtered) at its four top corners and centre is flagged; RenderGroundShadow and RenderCasters skip it (separately meshed structures; merged meshes are never wholly under ground, the shader handles them). One log line when the count changes.
- VBase::RenderGroundShadow: after the loop the depth test is set back off and the depth function to its value before, so the draws after it (cloud shadows ...) inherit pass P1's old depth state; nothing else of the state is touched.
Not changed: vessel ground shadows (pass P0), particle shadows, the plane maths. ShadowMeshTechExVS's SPIR-V changes with SceneShadows 0 too (intended: the user asked for the fix in both settings; only pass P1 uses it).
