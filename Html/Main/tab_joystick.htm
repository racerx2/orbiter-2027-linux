Controllers

Joysticks, throttles, rudder pedals, button boxes and other game controllers work all at once, and can be plugged in and out while Orbiter runs. This page shows them and what they do. The same page is in the in-sim Options dialog (main menu, options, Controllers), so bindings can be changed in flight too.

Controllers

The table lists the controllers found, with the name the bindings use for each. Select one to see its axes and the buttons pressed now.

  • Rename... gives the controller another name. Its bindings in every profile change with it.
  • Calibrate...: move every axis through its whole travel, let go of everything and press Done moving. Check the kind of each axis, then Save. A centring axis (stick, rudder) keeps where it rests as its centre; a lever or toe brake takes the middle of its travel. Reset to the raw range removes the calibration. Nothing acts in flight while this window is open.

No access

A controller the desktop doesn't give to the user (some button boxes, and pedals without buttons) is listed with the udev rule that does, for /etc/udev/rules.d/71-orbiter-controllers.rules.

Controllers work while Orbiter is in the background

If ticked, the controllers keep flying when another window has the focus, for example an external MFD or a map on another screen. The keyboard and the mouse stay with the Orbiter window.

Bindings

For picks the profile: all vessels (Global), or one vessel class (type to search). A vessel class's bindings come on top of the ones for all vessels, which are shown in grey under it.

  • Add...: press the control (a button, the hat, a dial, a key, or a mouse button; left and right with Shift, Ctrl or Alt), or move an axis through at least 40 % of its range (a centred stick to one end). Then pick what it does: an Orbiter function, a key or key combination, an analog control (attitude, throttles, trims, flaps, toe brakes, views), an MFD button or a shift layer.
  • For a button: the shift layer it belongs to, how it acts (held, once on press, once on release, both for a toggle switch, toggle, repeat), and the view it works in.
  • For an axis on an analog control: invert, dead zone, saturation, curve and scale, with the value it gives now. Part of an axis can work as a button (a detent or lever position).
  • Change... (or a double click) edits the selected binding. Changing a grey binding gives this vessel class its own. Remove deletes it.
  • A binding with a warning sign takes a key keymap.cfg uses for an Orbiter function. Its tooltip also lists what else the control does in this profile (all of them act).
  • Reset... puts things back to Orbiter's defaults: the bindings for all vessels (as Orbiter first made them from the old joystick settings), the selected vessel class's own bindings (removed, so those for all vessels apply), every vessel class's own bindings, or the keyboard keys in keymap.cfg. Each old file is kept next to it as .bak. Controller names and calibration stay.

Every change is saved at once to Config/Input (Global.cfg, Vessels/<class>.cfg; the controllers' names and calibration in Devices.cfg) and acts at once. The files can still be edited by hand, and their comments are kept; the format is in the User Manual, section Advanced Configuration, Controllers and bindings.

The first time this version runs, Global.cfg is made from the old joystick settings, so a joystick works as it did before.
